What's real here: the four decision engines (crop match, irrigation trigger, harvest window, green manure match) run on agronomy rules — soil type, rainfall, water need, crop duration, and nitrogen fixation — the same variables an ML model would learn from field and weather data.

What a production version adds: live weather API + soil sensor / satellite soil data feeding these same rules automatically, a trained model replacing hand-set thresholds as real usage data comes in, and regional language + voice input for accessibility.

Why rule-based first: it's explainable — a farmer or judge can see exactly why a suggestion was made, which matters for trust before you introduce a black-box model.
